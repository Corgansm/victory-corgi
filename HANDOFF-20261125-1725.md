## Mask blocks: what was learned offline (victory-shader builds on Linux; examples/dis.rs written there, not in the repo)
- The 18 writers and the classifier are on disk and disassemble. 0c028454b58543f0 is not a plain clear: it is the
  per-tile classifier pass (425 instructions, groups of 16x16, waves of 16x4 pixels) and stores 0 to the mask first.
  So a grey pixel is a value some class shader stored, not a pixel nobody wrote.
- Thread groups: 804b, 56f3, 922e, be6c, 20b7, f133 are [8,16] (a thread writes a checkerboard pair of pixels:
  image_store at [v1,v0] and at [v20,v0]); the other twelve are [16,16].
- Forms with default switches: f133e35efed2a48a (29,157 instructions, the largest) translates only as
  "wave-wide branches, last resort" with its groups split one host group a console wave; ce79e9eba7ae0348,
  fa0bd10a35bfef3c and 20b78ee12ecdb57d take "paired lanes, before an approximate form"; the other fourteen
  "without skips, scalars followed". ce79 and fa0b keep scalars in the lanes of v68 (v_writelane / v_readlane 0..15).
- The grey sits in 16x16 tiles but covers only part of each (frame 6800: 475 tiles, mostly 12 to 37 % of the tile,
  no fixed position in the tile): a per-lane result that is tile-constant, not a tile nobody processed.
- In 922e the tile-wide min/max (0xace4-0xad98) only decides whether a lane takes the long path at 0xaea4; it is
  recognised as Shape::Active(MinF/MaxF) (wave.rs), lowered by Lower::shape / paired_shape.
- A static scene has no grey tiles (frame 2971, the cell: 4 cells). They need motion.
- Not done: which class shader stores the grey. Cheapest test: launch with skip_pipelines=<one or two hashes> and
  record a frame in motion; the class whose skipping removes the grey is the one (start with 65de113e23fa4fdd and
  804b342cb4b9d1e9, the two with no shadow-map sample, then f133).
- The compute trace picks a thread by dispatch thread id, which for these tile-list dispatches is not a pixel:
  a grey pixel cannot be picked for a trace as the debugger stands.
